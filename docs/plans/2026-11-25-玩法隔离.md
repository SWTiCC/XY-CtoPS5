# 玩法隔离（键鼠 / 手柄）实施计划（2026-11-25）

## 1. 边界：做 / 不做

**做**：把「键鼠玩法」和「手柄玩法」从「同一个进程里两份对象都活着、只是用闸门挡住写入」改成
**同一时刻只有一侧被实例化**：

- 手柄玩法下**不存在**：`InputSource`（pynput 监听 / Raw Input 窗口 / 键盘钩子 / 鼠标钩子 /
  全局热键 F8）、光标锁定、透明覆盖层、8ms Raw Input 消息泵。
- 键鼠玩法下**不存在**：DualSense HID 读取线程与句柄、USB 触觉音频端点、手柄页 100ms 轮询、
  扳机过滤/灯条/马达的本地记录、触觉环境探测。
- 切换玩法时：先整侧拆掉旧玩法（含把手柄扳机/马达放掉、把按住的键松开），再整侧建起新玩法。

**不做**：

- 不改远程会话（`bridge`）这一层：主机反馈回调仍然常驻注册，但全部经 `_pad_forward_active()`
  闸门，键鼠玩法下不会碰到实体手柄。这就是用户说的「共同的远程逻辑」。
- 不改「已连接时禁止切换玩法」的限制（先断开再切），这是既有交互，保持不动。
- 不重写 `_tick_loop` / 映射层 / 手柄协议层。

## 2. 约束与复用

- 全部复用现有对象与它们的 `start/stop/close`：`InputSource.stop()` 已经负责解钩子、注销热键、
  销毁 Raw Input 窗口、停监听；`DualSenseReader.stop()` 已经负责关 HID 句柄并复位触觉模式；
  `UsbHaptics.close()` 已经负责收音频流。本计划只负责**调用时机与顺序**，不新增释放逻辑。
- 不引入新依赖、不改配置格式、不改公开接口（`Ps5KbmApp` 仍是对外唯一入口）。

## 3. 架构：模块、依赖方向

只有一个模块动：`ps5kbm/app.py`（UI/编排层）。新增一节「玩法隔离」：

```
_leave_input_side(side) ─┬─ _release_keyboard_side()
_enter_input_side(side) ─┴─ _release_controller_side()
                          ├─ _init_keyboard_side()
                          └─ _init_controller_side()
_sync_input_lifecycle()  = 先拆另一侧，再建当前侧（幂等）
```

单一事实来源：**`self._source is None`** 表示键鼠侧不存在；
**`_controller` 线程未启动 + `_usb_haptics` 未打开** 表示手柄侧不存在。
所有入口（启动、切换玩法、连接、断开、重建映射、关窗）都走同一组方法，禁止各自散写 stop/start。

## 4. 契约

- `_sync_input_lifecycle()`：无参数、无返回值、幂等；按 `_current_side()` 收敛状态。
- `_init_*` / `_release_*`：各自只碰自己那一侧的属性，可重复调用。
- 顺序契约：**先 leave 再 enter**；leave 手柄侧时先写释放报告（扳机/马达）再关 HID；
  leave 键鼠侧时先松键（发 `release_all`）再解钩子。

## 5. 数据与状态

| 状态 | 键鼠玩法 | 手柄玩法 |
| --- | --- | --- |
| `_source` | 对象存在（连上会话才 `start()`） | `None` |
| `_pump_job` | 有（8ms） | `None` |
| `_poll_job` | `None` | 有（100ms） |
| `_controller` 线程 | 未启动（`stop()` 过） | 运行 |
| `_usb_haptics` | 已 `close()` | 按连接/开关懒打开 |

## 6. 失败与边界

- 释放失败（钩子解不掉、HID 关不掉）只记日志，不让程序崩；`stop()` 尽量可重入。
- 未连接时进入键鼠玩法：只建对象不启监听（保持原有「连上才装钩子」的行为，避免断开后 F8 还能
  进一个没有会话的捕获态）。
- `_apply_capture_state` / `_apply_key_state` / `_toggle_capture` / `_apply_capture_state` 的
  `_source` 为空分支必须有兜底，否则关窗/断开路径会 AttributeError。

## 7. 演进与扩展点

- 之后若要允许「连接中直接切玩法」，只需去掉 `set_input_mode` 里的拦截弹窗——
  生命周期已经支持热切换（tick 循环每帧读 `_controller_mode()`）。
- 新增第三种玩法时，按 `_leave_input_side` / `_enter_input_side` 加一个分支即可。

- `python -m unittest discover -s tests`（全绿，含新增用例）

## 10. 熵账本

**偿还**：`_connect` 无条件 `_source.start()`（手柄玩法也装钩子/热键）、`__init__` 无条件启动手柄
读取线程并在键鼠玩法下用闸门兜底、`_reload_config` 与 `_rebuild_mapper` 各自复制一份 InputSource
构造代码（现在统一到 `_new_input_source`）。

**新增债**：`app.py` 行数继续增长（已是巨型编排对象）；`_source` 变成可空后，所有使用点都要判空。
偿还计划：若再加第三种玩法，就把本节的四个方法抽成 `ps5kbm/mode_runtime.py`。

## 11. 实际结果（执行后回填）

**与计划的偏差**：

1. `dualsense.DualSenseReader` 原来继承 `threading.Thread`，而 `Thread` 不能重复 `start()`，
   所以「切走再切回手柄玩法」会直接抛 `RuntimeError: threads can only be started once`。
   计划里以为「`stop()` 已经够用」，实际改成**组合**（内部持有 `_thread`，提供 `is_alive()`），
   这样 `stop()` 之后还能 `start_reader()`。
2. 触觉环境探测（`haptics_usb.describe_environment()`）从 `__init__` 移到 `_init_controller_side()`，
   键鼠玩法下连 PortAudio 都不初始化。
3. Raw Input 消息泵与手柄页轮询都改成「跟着玩法走」的 Tk 定时器（`_pump_job` / `_poll_job`），
   键鼠玩法空闲时不再每秒 125 次空转。
4. `_connect` / `_disconnect` 也统一走生命周期：连接走 `_sync_input_lifecycle()`，
   断开走 `_release_keyboard_side()`（键鼠侧整套扔掉，下次连接重新建）。

**验证结果**：

- `python -m unittest discover -s tests`：**200 全绿**（新增 `tests/test_mode_isolation.py` 11 项）。
- `python -m compileall ps5kbm tests`：通过。
- 实机探针 `tests/_tmp/mode_switch_probe.py`（真 InputSource + 真 DualSenseReader，只用假会话）：
  - 键鼠玩法启动：`键鼠侧=有 started=False pump=False | 手柄侧 alive=False poll=False`
  - 连接后：`started=True listening=True raw_ok=True pump=True`
  - 断开：`键鼠侧=None`，且捕获中按住的键补发了 1 次松键包
  - 切到手柄：`键鼠侧=None | 手柄侧 alive=True poll=True`
  - 切回键鼠：`键鼠侧=有 started=False | 手柄侧 alive=False`
  - 再次连接：钩子 / 热键 / Raw Input 窗口二次注册正常（`listening=True raw_ok=True`）
- 手柄玩法启动（临时把 `controller.mode` 改成 `controller`）：`键鼠侧=None`、`手柄侧 alive=True`
  ——启动时就不会创建任何键鼠对象。
- 未验证：真机跑一局游戏下的手感（本轮改动只动生命周期，不动协议与触觉参数）。
