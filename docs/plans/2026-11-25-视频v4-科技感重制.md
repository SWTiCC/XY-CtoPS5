# 视频 v4 重制：修截断 + 去重复 + 科技感升级（2026-11-25）

## 1. 边界：做 / 不做

**做**

1. 修掉所有旁白被硬切的问题（用户反馈「话没说完截断」）。
2. 删掉「开头讲原理」的重复：`01_intro` 旁白重写为产品定位，原理只由 `02_diagram` 讲一次。
3. 按 `Video_Shotcraft` 的 `scanline-annotate-focus` + `fui-hud-moves` 两张镜头卡，把标注镜头升级成
   扫描线 + L 形取景框 + 逐字打字标签 + HUD 状态行。

**不做**

- 不改软件源码（`ps5kbm/`），不动已发布的 v0.3.0。
- 不重拍截图（现有 v0.3.0 截图已是准确版本）。
- 不换 BGM、不重做音效素材（沿用 `bgm-tech-house` + 12 个 Mixkit SFX）。

## 2. 约束与复用

- 渲染：Remotion 4.0.484，1920×1080@30fps，Chrome 本地可执行文件，`--concurrency=4`。
- 旁白：Edge TTS `zh-CN-XiaoxiaoNeural`；Python 进程只能写 `.venv`，故 `.venv/voice/` 为中转站。
- 复用镜头卡：`scanline-annotate-focus`（扫描线严格匀速、取景框 spring damping 15 / stiffness 210、
  外扩 76px、臂长 40→26 晚 3f、标签 ft+5 起逐字 2.2 字/帧）与 `fui-hud-moves`（角标咬合）。
  参数不降档，只把机器色从钴蓝换成产品青 `#38e1ff`。
- 复用现有组件骨架：`Backdrop` / `StarField` / `Halo` / `Cap` 保持不变。

## 3. 分层与依赖方向

`Main.tsx` 内按「背景层（Backdrop/Halo）→ 镜头层（ScanShot / DiagramScene / FullImageShot）→ HUD 层 →
音频层（Bgm / SfxTrack）」组织，镜头层不直接读时间轴常量以外的东西，全部时长由 `S` 单一来源提供。

## 4. 契约

```ts
type ScanTarget = {
  x: number; y: number; w: number; h: number; // 相对截图的比例（0-1），已按真实截图量取
  head: string;   // 标签主名（等宽大写，如 "PRESET"）
  detail: string; // 标签副文（如 "gta6 · 一整套按键"）
  tag: 'right' | 'below' | 'above';
};
```

`ScanShot` 必须保证：`每个 target 的触发帧 = 扫描线越过 (y+h) 下缘的帧`，且严格单调、间隔 ≥ 6f。

## 5. 数据与状态

- `S`（时间轴）为唯一事实来源，`PS5_TOTAL = 末段 from + duration`，由代码计算，禁止手写魔数。
- 每段 `duration = ceil(音频秒 × 30) + 呼吸余量`，余量 33~36f；GTA6 两段与结尾额外加静止 hold。
- 音频时长由 `measure-audio.mjs`（`@remotion/media-parser` + `nodeReader`）实测，写进计划供核对。

## 6. 失败与边界

- 扫描线扫完到场景结束之间必须留 hold，避免「扫完就切」的急刹。
- 场景被 Voice 截断是本次要修的缺陷：任何 `duration < 音频帧数` 都算缺陷，由第 9 节的校验脚本拦截。
- 标签不得溢出画面右/下边缘：`tag: 'right'` 的目标 x+w 须 ≤ 0.82。

## 7. 演进

截图尺寸今后若变化，只需按比例改 `Target` 的 `x/y/w/h`；`head/detail` 文案与 `tag` 位置可独立调整。

## 11. 实际结果（执行后回填）

### 做成的

| 项 | 结果 |
|---|---|
| 旁白截断 | 修掉。14 段全部 `duration = 实测帧 + 33~36f`；GTA6 两段各 +120f 静止、结尾 +77f |
| 开头重复 | `01_intro` 重写为「用键盘鼠标玩 PS5 游戏。XY-CtoPS5，开源免费。两种玩法：键鼠映射，或者 DualSense 手柄直通。」（10.87s，原 19.90s），原理只由 `02_diagram` 讲一次 |
| 科技感 | 新增扫描线（匀速 + 140px 余晖 + 点阵 + 侧游标 + Y 读数）、L 形取景框（spring 15/210 过冲咬合 + 对焦闪）、逐字打字标签、左栏 HUD（SIGNAL 编号 / 目标清单 / SCANNING→RESOLVED / 进度）、右侧竖排刻度、底部基线、开场刻度环 |
| 图片背景 | 按实测边界重裁：左右各去 10–13px 桌面、底部去 23px 桌面；窗容器再加圆角裁切 |
| 时长 | 6232f = 3 分 27.7 秒（原 4930f 却切掉旁白） |

### 与计划的偏差

- **原理段没有删**，而是保留并升级。用户说的「开头不用讲原理」按字面理解为
  「开场那段不要讲原理」；`02_diagram` 才是原理段，它是全片科技感最强的段落，
  删掉反而丢了画面。开场旁白改成只讲定位，与原理段彻底解耦。
- **`Main.tsx` 没有继续膨胀**：抽出 `theme.ts` / `timeline.ts` / `ScanShot.tsx` 后，
  `Main.tsx` 从 898 行降到 816 行（新增 3 个文件分担），但仍超 500 行阈值，
  债记在账上；下一步可再抽 `Backdrop.tsx` 与 `scenes.tsx`。
- **新增验证脚本** `verify-timeline.mjs`：解析 `timeline.ts` 的 voice/duration，
  与 mp3 实测帧数交叉比对。`timeline.ts` 的构建期断言只能防「duration < voice」，
  防不了「voice 本身写小了」，所以必须有这个外部校验。本次运行 14/14 合格。

### 计划外修掉的缺陷

- **原理段连线整条不显示**：`<linearGradient>` 用了默认 `objectBoundingBox`，
  而水平线段的 bbox 高度为 0，渐变退化导致描边不可见。改 `gradientUnits="userSpaceOnUse"`。
- **开场标题的矩形亮块**：`overflow:hidden` + `textShadow` 把 60px 外发光硬切成矩形边。
  去掉 `clipPath`/`overflow`/glint，改「模糊聚焦 + 字距收拢 + 发光呼吸」揭示。
- **截图窗标题栏被推镜裁掉**：`transformOrigin` 从 `50% 50%` 改为 `50% 18%`，
  裁切改落在底部日志区。

## 12. 独立终检后的返工（2026-11-25）

派了独立上下文 subagent 逐帧审查，出 3 严重 / 8 一般 / 8 建议。返工记录如下。

### 根因：窗内文字标签在密集 UI 上必然遮挡

三处严重问题（S1 标签被窗口裁掉、S2 两个标签互压、S3 标签盖住「添加映射」按钮）
是同一个根因：`Label` 的「右侧放不下就落到下方」策略，在 1120px 宽的截图窗里
几乎必然落到下一行内容上；密集两行（映射页预设行与编辑模式行间距仅 9px）时还会互相重叠。
逐个挪标签是治标。

**改法**：窗内**不再挂任何文字**。只保留取景框（加了外发光，否则深色截图上太弱）
和一枚 27px 编号徽章（贴在 bbox 左边缘外侧、沿高度居中，既不压框内内容也不压上方说明行）；
所有说明文字移到左栏信息面板逐字打出，与框靠编号 `01/02` 和出现时机对应。
左栏同时补了一组竖向刻度，填掉中段空白。
