# ps5-kbm App（GUI 全流程）实施计划（2026-11-22）

## 1. 边界：做 / 不做

**做**：
- 一个 Tkinter 桌面应用，把「扫描/配对 → 连接会话 → 键鼠映射 → 捕获运行」全部打通。
- 映射规则模块化、可视化编辑：支持「一个键盘键 → 手柄组合键（同时按）」与「序列宏（依次按）」。
- 捕获运行时**拦截 PC 输入**：键盘、鼠标点击与鼠标移动都不再传给 Windows；
  鼠标位移通过 Raw Input 读取（不依赖光标位置），因此不再需要把光标锁在屏幕中心。
- 连接状态、运行日志、捕获开关在界面内可见；配置与预设可保存/切换。

**不做**：
- 不做视频/音频串流（画面仍走采集卡）。
- 不做多手柄/多人。
- 不做曲线编辑器图形化（先用数值 + 预设）。
- 不实现 Remote Play 协议（继续复用 playdirector / pyremoteplay）。

## 2. 约束与复用

- Python 3.12 + 既有 `.venv`；Tkinter 为标准库，不引入新 GUI 依赖。
- 复用 `bridge.py`（配对/会话）、`mapping.py`（映射引擎）、`config.py`（预设合并）。
- 新增 `raw_mouse.py`：Win32 Raw Input（`RegisterRawInputDevices`）读相对位移。
- 键盘拦截用 `pynput.keyboard.Listener(suppress=True)`；鼠标点击拦截用 `pynput.mouse.Listener(suppress=True)`。
- 线程模型：Tkinter 主线程（UI）+ asyncio 线程（会话与发送）+ pynput 监听线程 + Raw Input 线程。

## 3. 架构：模块、依赖方向、公开接口

```
app.py（Tkinter UI）
  ├── config.py        配置/预设/动作模型
  ├── mapping.py       纯映射引擎（状态合成 + 组合键 + 序列）
  ├── input_source.py  键盘/鼠标拦截 + Raw Input 位移 + 热键
  ├── raw_mouse.py     Win32 Raw Input 读取器
  └── bridge.py        Remote Play 会话与发送
```

依赖方向：`app → {config, input_source, bridge, mapping}`；`mapping` 不依赖 IO；`raw_mouse` 只依赖 ctypes。

**关键接口**：
- `Action`（配置模型）：`kind: "button" | "chord" | "sequence"`；`buttons: [str]`；`steps: [{button, hold}]`。
- `InputMapper`：`on_key` / `on_mouse_button` / `on_mouse_delta` / `tick(dt)`；
  兼容旧配置（字符串直接当 button）。
- `RawMouseReader(on_delta)`：后台线程，回调 `(dx, dy)`。
- `InputSource`：`start(suppress=True)` / `stop()` / `capturing` / `poll_mouse_delta()`。

## 4. 契约

- 动作序列化：
  ```json
  "keyboard_buttons": {
    "space": "CROSS",
    "g":     {"chord": ["L1", "R1"]},
    "h":     {"sequence": [["UP", 0.05], ["CROSS", 0.05]]}
  }
  ```
- 序列在按下时触发一次，期间独占该动作的按钮集合；新按键打断旧序列。
- 捕获模式下所有键盘事件被吞；F8/F9 仍由监听器内部处理（不会被传给 PC）。
- 鼠标 move/click 全部被吞；位移来自 Raw Input，光标不再被锁定。

## 5. 数据与状态

- 配置：`config.json`（含动作模型、hotkey、鼠标参数）。
- 凭据：`credentials.json`（不改格式）。
- 运行时状态仅内存：按下键集合、序列调度器、捕获开关、连接状态。
- UI 状态：连接页字段、映射表草稿（保存前不落盘）。

## 6. 失败与边界

- 配对失败/会话失败：错误码原样显示在日志区，并给出下一步提示。
- 拦截失败（hook 安装失败）：自动降级为非拦截模式并提示。
- Raw Input 初始化失败：降级为光标轮询模式（旧逻辑）。
- 热键冲突：热键在捕获模式仍可用；界面也提供手动开关。
- 关闭窗口：停止捕获 → 释放会话 → 退出，避免主机卡住按键状态。
- 序列执行中被停止：释放所有按钮。

## 7. 演进与扩展点

- 动作类型可继续扩展（`kind` 分发），例如"按住时持续"。
- 预设可导出/导入，便于分享 GTA6/其他游戏配置。
- UI 主题/布局与引擎解耦，后续可换 PySide6 而不动核心。

## 9. 验证

- 单测：旧格式、chord、sequence（含打断）、release_all。
- 本机可验证：GUI 启动、配置保存/加载、Raw Input 位移计数（不连 PS5）。
- 需要用户验证：配对/连接、PS5 实机输入、拦截是否真的不落到 PC。
- 验收：主界面 WASD 可控；按 G 触发 L1+R1；捕获时在记事本打字不会出现字符。

## 10. 熵账本

**新增的债**：
- Tkinter UI 与业务逻辑通过回调耦合，后续若换 UI 需要抽一层 controller。
- Ray Input 与 pynput 双监听并存，两者生命周期必须一致（统一在 InputSource 管理）。
- 序列宏没有跨平台实现（Windows only）。

**偿还计划**：
- 若 UI 复杂度继续上升，抽 `AppController`（连接状态机 + 捕获状态机）独立于 Tkinter。
- 若需要 macOS/Linux，把 raw_mouse 换成对应平台的相对位移实现。
