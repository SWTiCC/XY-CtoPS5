# USB 原生触觉输出（音频触觉）开发文档

> 适用范围：手柄玩法 + **USB 连接**下的 DualSense 触觉（游戏震动）。
> 蓝牙没有四声道音频端点，硬件上做不了；那时只能用「经典马达」或关闭（手柄页「震动方式」）。
> 相关代码：`ps5kbm/bridge.py`（收包 / 解析 / 去重 / 排队）、`ps5kbm/haptics_usb.py`
> （重采样 / 输出到端点）、`ps5kbm/dualsense.py`（输出报告里的音频寄存器、触觉模式）。

## 1. 它解决什么问题

PS5 的 DualSense 触觉走的是**一条独立的 3kHz 触觉音频流**（不是经典马达的 0~255 值）。
远程游玩会把它和普通游戏音频（Opus）混在同一条 AV 流里下发，需要我们自己认出来、
按 3kHz 立体声 PCM 处理，再写进手柄四声道音频端点的 **3/4 声道**（1/2 是扬声器，写 0）。

## 2. 数据链路（从网络包到执行器）

```
Takion AV 包（AUDIO, type=3）
  └─ bridge._patch_haptics_audio 的 handle()
       ├─ header_end = 1 + 0x11 + 1（有 NALU 信息再 +3）
       ├─ msg[header_end] == 0x02 → 触觉帧（普通音频是别的值）
       ├─ dword2 解析：total = ((dword2>>16)&0xFF)+1, fec = (dword2>>4)&0xF,
       │                src = dword2&0xF, unit_size = (dword2&0xFFFF)>>8
       ├─ cipher.decrypt(msg[header_end+1:], key_pos) → 明文负载
       ├─ feedback.audio_units()：只留前 src 个真实单元，后面是冗余校验单元
       ├─ bridge._take_fresh_haptic_frames()：按 frame_index 去重
       │    └─ 只有「比上一帧新」才要；重复包 / 乱序旧帧丢弃
       └─ 丢进 _haptics_queue（maxsize 16）→ 独立线程 haptics-decode 交给 app
            └─ app._on_haptics_pcm → UsbHaptics.feed()
                 ├─ 3kHz 立体声 s16 → 设备率（48kHz）四声道，写 3/4 声道
                 ├─ 跨包连续线性插值（_next_out_src 浮点游标，接缝不留平台）
                 ├─ 抖动缓冲：攒够 40ms 才播 / 欠载后攒回 40ms 再继续
                 ├─ 队列上限 100ms，超了整段清空
                 └─ 没数据 → 输出静音（带 2ms 淡出），不保持上一个样本
```

## 3. 关键常量（`ps5kbm/haptics_usb.py` 顶部）

| 常量 | 当前值 | 含义 / 调整注意 |
|---|---|---|
| `_SOURCE_RATE` | 3000 | 触觉源采样率，固定；主机就是按 3kHz 立体声 s16 发 |
| `_QUEUE_SECONDS` | 0.10 | 队列上限，超了整段清空；调小会让突发时更容易清空 |
| `_PREBUFFER_SECONDS` | 0.04 | 起播 / 欠载恢复的缓冲量；**调小更跟手但更容易欠载抽动** |
| `_FADE_FRAMES` | 96 | 欠载时淡出长度（约 2ms@48k），只为去咔哒声 |

## 4. 为什么不做「播放速率自适应」

试过按缓冲余量把播放速度在 ±20% 内微调来追主机帧率，结果在 47~60Hz 的低频震动上
等于持续变调 + 相位来回拉，手感反而变成「不断抽动」。现在的策略是**固定速率**：
宁可偶尔静音一下，也不让已经出来的震动变调。

## 5. 诊断怎么看

触觉相关日志默认安静：每 5 秒只有一条内部统计，且**只在出现新的欠载时才写 INFO**，
其余走 DEBUG。日志里搜「触觉流」：

```
触觉流：收到 501 包 / 写入 501 包 / 峰值 28710 / 包长 120 / 欠载 2（新 0）/ 恢复 2 / 队列 1920/4800 帧（上限）…
```

- `收到`：每 5 秒的触觉包数，正常约 500（100 包/秒 = 10ms/包 = 实时）；
- `欠载（新 x）`：回调没拿到数据的次数；`新 0` 表示这段时间没出问题；
- `队列 x/y`：当前排队帧数 / 上限，正常 1900~2900（40~60ms）；
- `触觉模式=True`：手柄处于「音频触觉」模式（此时不发经典马达，两者互斥）。

## 6. 常见故障对照

| 现象 | 先看什么 | 结论 |
|---|---|---|
| 手柄完全没震动 | 日志有没有 `已打开 DualSense 触觉端点…48000 Hz，4 声道` | 没有 → 手柄没插 USB / 端点被占用 |
| 有震动但游戏内没有 | `触觉流` 行的 `收到` 是否为 0；`触觉模式` 是否 True | 收到 0 → 主机没发；触觉模式 False → 马达使能位把触觉压掉了 |
| 不断抽动 | `欠载（新 x）` 是否频繁 >0；`队列` 是否长期贴近 0 | 是 → 主机断流或缓冲太小（调大 `_PREBUFFER_SECONDS`） |
| 震动像噪音 / 跟着别的声音走 | `峰值` 是否长期接近 32767 | 说明主机这条 3kHz 流本身带入了高频内容，属协议带宽限制 |

## 7. 扩展指南

- **想更跟手**：`_PREBUFFER_SECONDS` 从 0.04 降到 0.025（代价是突发时更容易欠载）。
- **想做低频整形**（把 600Hz 以上的杂音压掉）：加在 `UsbHaptics._to_block` 输出前，
  一阶低通即可；注意不要和「经典马达」混用（两者互斥）。
- **想支持多手柄各自触觉**：`bridge._take_fresh_haptic_frames` 目前只维护一个全局帧游标，
  需要按手柄分别维护。
- **想换输出后端**（不用 PortAudio）：实现一个和 `UsbHaptics` 同接口的类
  （`ensure/feed/close/stats/target_frames/is_open`），在 `app.__init__` 里替换即可。
