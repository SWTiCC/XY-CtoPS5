# 预设与扳机调参键开发文档

## 一、功能用途

- **预设**：一整套配置（内含默认 / 驾驶等所有模式）。
  - 下拉**选中即应用**；「新建预设」创建一套空映射（只有一个「默认」模式），
    自己新建的预设每次编辑后自动写回文件；「另存为…」把当前配置复制成新预设；
    「删除」只删用户预设，内置 `gta6` 只读。预设只换键位，不动鼠标手感参数。
- **映射改键**：列表每行「改键」可以把一条映射的来源键（如 E）重新捕获成任意键盘 / 鼠标键，
  动作不变；改到已被占用的键会询问是否覆盖，改到全局热键 / 模式切换键 / 调参键 / 左摇杆方向键会被拒绝。
- **扳机调参键**：捕获时用哪几个键调整 R2 / L2 的输出深度。默认沿用旧行为
  （R2 滚轮上/下，L2 `=` / `-`），可以在运行页点键名改成任意键盘键、鼠标键或滚轮；
  这四个键**只在捕获中生效**，改键时同样会做占用校验。

## 三、工作原理

### 1. 调参键匹配

`config.trigger_adjust_keys(cfg)` 输出固定顺序的四个键（空值回落默认）：

```
r2_up → r2_down → l2_up → l2_down
```

输入层收到任何键盘 / 鼠标事件后，先调 `adjust_action_for()` 匹配；命中就回调 `app._on_adjust(action)`。
回调跑在监听线程，只把动作丢进 `_ui_queue`，界面线程的 `_apply_adjust()` 再把深度 ±0.1（夹在 0~1）、
更新滑条与右上角提示，并立刻写盘（所以重启还是上次的值）。`+` 视为 `=` 的别名。

调参键优先于映射，但**只在捕获中生效**（`InputSource._handle_key` / `_handle_mouse` 里都有
`if adjust and self._capturing`）。否则程序开着时在别的窗口打字按到 `-` / `=` 会偷偷改深度。

### 2. 改键

运行页扳机行右侧两个按钮显示当前键（`↑ 滚轮上` / `↓ 滚轮下` 等）。点击 → `KeyCaptureDialog(allow_wheel=True)`
→ 捕获到键名后先过 `app._global_key_conflict()`（热键 / 切换键 / 其它调参键 / 方向键 / 已映射的键都算冲突，
改回自己不算）→ 写回 `config.json`（`r2_up` 等字段）并调用 `source.set_trigger_adjust()` 立即生效。
模式切换键走同一套校验。

### 3. 预设

- 预设文件在 `presets\<名字>.json`（用户目录优先于内置 `ps5kbm/presets`）；
- **新建预设**：`config.new_empty_config(name, base)` 生成"只有默认模式、三组映射为空"的配置；
  非映射设置（热键 / 切换键 / 调参键 / 目标窗口 / 手感 / 扳机深度）沿用传入的 base，
  否则新建一个预设会把用户的切换键悄悄重置回默认 F9。写盘后立即 `apply_preset(name)` 切过去；
- **切换即应用**：预设下拉绑定 `command=app.apply_preset`，选中的名字直接加载；
- **应用**：读预设文件 → 只替换 `modes` / `ruleset`（顺手按名字加载那套自动切换规则）/
  `mode_switch` / `current_mode`（连同 `auto_hold` / `auto_release` 两个去抖默认值），
  **不动** `mouse` / `left_stick` / 扳机深度；
- **自动保存**：`app._persist()` 在写 `config.json` 后，如果当前预设是用户预设，再写回预设文件；
  内置预设不覆盖。所以切换来切换去不会丢改过的键位；
- **内容来源校验**：`app._preset_owner` 记录内存里的 modes 是从哪个预设加载的；
  只有 `_config.preset == _preset_owner` 时才允许写回预设文件。删除当前预设时先加载回落预设
  （而不是只改名字），否则旧内容会被写进另一个预设，把对方清空。
- 「删除」只删用户预设；删掉当前预设会切到另一个可用预设；删掉的正好是 `config.json` 记录的预设时，
  `config.load_config` 会退化为"只用用户配置"而不是启动失败。
- **文件读坏**：`config.load_config` 遇到解析失败的 `config.json` 会改名成 `config.json.broken` 留档，
  再按预设启动；`app.apply_preset` 遇到坏预设会弹窗说明，并把下拉框恢复到实际生效的预设
  （避免出现"下拉框显示 A、实际还是 B"）。
- **模式不能重名**：`app._mode_label_taken()` 拦住重命名 / 新建；老配置里已经重名的模式，
  `app._mode_option_labels()` 会在下拉框里补内部 id 区分（否则第二个同名模式永远选不中）。
- **写盘是原子的**：`config._write_json()` 先写 `.tmp` 再 `os.replace`，断电 / 崩溃不会留下半截 JSON。

### 4. 映射改键

`app.rebind_mapping(source)`：用 `KeyCaptureDialog` 捕获新键 → 检查 `_hotkey_reason`
（**只有捕获热键 F8 是硬禁**：捕获中按它只会开关捕获）→ 再检查 `_mapping_key_conflict`
（模式切换键 / 扳机调参键会被输入层优先处理，绑上去映射永远不触发，所以先问一句，确认后仍可绑；
左摇杆方向键不算冲突：同一个键走路 + 按键是正常玩法，只在日志里说明两个动作都会触发）→
目标键已存在时确认覆盖 → 从原表 `pop` 出动作、写进新表 → 重建 mapper 并渲染列表。
键盘表和鼠标表分开存，跨表改键就是"从 keyboard_buttons 挪到 mouse_buttons（或反向）"。
「添加映射」走同一套规则，重复键会先问是否覆盖。

## 四、怎么扩展

- **加一个新的调参动作**：`config.TRIGGER_KEY_DEFAULTS` 加键 → `config.TRIGGER_LABELS` 加界面名 →
  `input_source._ADJUST_ORDER` 加顺序 → `app._apply_adjust` 里处理 → 运行页加一行。
- **加一种「占一个键」的东西**：只改 `config.key_conflict` 的参数与判定顺序，调用方把新占用项传进去。
- **预设导入 / 导出**：`config.save_preset` / `load_preset` 已按文件工作，套一层文件选择框即可。
- **预设复制 / 重命名**：读旧文件 → `save_preset(新名, build_config(raw))` → 需要时 `delete_preset(旧名)`。

- `python -m unittest discover -s tests`（`test_config.py` / `test_input_source.py` 覆盖默认值、校验、
