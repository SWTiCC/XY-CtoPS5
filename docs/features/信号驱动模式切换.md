# 信号规则与模式自动切换 开发文档

代码位置：`ps5kbm/signal_rules.py`（事实表 + 条件树）、`ps5kbm/rule_engine.py`（规则与状态机）、
`ps5kbm/legacy_rules.py`（旧配置迁移）、`ps5kbm/mode_signals.py`（事实采集）、
`ps5kbm/config.py`（规则读写）、`ps5kbm/app.py`（装配）。

## 1. 它解决什么问题

开车和走路要用两套按键：车里 `w` 是油门、`s` 是刹车，车外 `w` 是往前走。
手动切换（`mode_switch`，默认鼠标侧键）能用，但每次上下车都要按一下，跑毒、抢车、
上错车这些高频动作里很容易忘。

这一层做的是「**看到主机给的信号，自动切到对应的模式**」：

- 判断只用主机下发的反馈数据（扳机效果、震动、触觉），**不要求接手柄**，也不写实体手柄
  （写手柄由 `app._pad_forward_active()` 那道闸门单独管）；
- 规则是**可编排的**：一条规则 = 一棵条件树 + 目标模式 + 去抖，能增删改（编辑页见第 6 节）。

## 2. 数据链路

```
PS5 ──Remote Play──▶ bridge（协议线程）
                       ├─ data_type 11 扳机效果块 ─┐
                       ├─ data_type 7  震动值     ├─▶ SignalWatcher（事实层）
                       └─ 触觉 PCM 3kHz  ────────┘        │
键盘（本机）── 映射成 △ 等按钮 ─────────────────────────────┘
                                                          │ facts.is_true()
                                    界面线程 100ms 定时器 ─▶ RuleEngine（规则层）
                                                              │ 决定
                                                              ▼
                                                    app._switch_mode(mode)
```

两个回调都在**闸门之前**喂事实，所以键鼠玩法下判定照常工作；单测里用假手柄验证过
一次都没写出手柄。

## 3. 叶子信号（`signal_rules`）

叶子按**信号类型**分，不绑定任何具体游戏——「GTA6 开车」不是特例，只是「阻力 + 前缀 FF 03 +
两侧」这样一条普通条件：

| 叶子 | 参数 | 说明 |
|---|---|---|
| **扳机效果** | 类型（`无效果 0x05` / `阻力 0x21` / `射击 0x25` / 自定义类型码）+ **参数前缀**（hex，可空）+ **作用侧**（两侧 / 任一侧 / 左侧 / 右侧） | 匹配「主机把某侧扳机设成了什么」 |
| 震动（马达） | — | 主机震动值 ≥ `RUMBLE_MIN`，`EVIDENCE_S` 内算数 |
| 触觉震动 | — | 触觉 PCM 归一化 RMS ≥ `HAPTICS_RMS_MIN`，`EVIDENCE_S` 内算数 |
| **按钮按下** | 哪个手柄按钮（△ / ✕ / ○ / □ / 十字 / L1…） | 映射层翻译后的按钮名，按下后 3 秒内为真 |

扳机的匹配口径：

1. 先过 `normalize_trigger_block`：主机在开车/刹车时会发 `0x05`（HID 里本该是 Off）但带非零
   参数，实机验证它表示阻力，所以统一改写成 `0x21`；写手柄也用同一份规则，避免两套口径；
2. **类型码**相等（自定义时按 hex 比对）；
3. 填了**参数前缀**就要求参数部分以它开头，不填只看类型；
4. 参数全零 = 「没设效果」，不算任何一种效果（`0x21` 全零不会当成阻力）。

**状态 vs 事件**是这一层最关键的一条：

- 主机**只在变化时**下发扳机效果。进车之后可能几分钟没有新包，所以扳机取「最后一次上报的值」，
  **不按时间过期**——旧实现按 2 秒窗口续命，结果就是「刚切到驾驶一两秒又自己切回默认」；
- 震动 / 触觉 / 按键是「某个瞬间发生过」，只能用时间窗口（`EVIDENCE_S` = 0.4 秒，
  按钮 3 秒）。

## 4. 节点（条件树）

| type | 字段 | 语义 |
|---|---|---|
| `trigger` | `kind`、`prefix`、`side`（自定义再加 `code`） | 扳机效果（见上一节） |
| `button` | `name` | 某个手柄按钮最近被按过（脉冲窗口内） |
| `rumble` / `haptics` | — | 两个事件型叶子 |
| `all` | `children` | 全部为真 |
| `any` | `children` | 任一为真 |
| `not` | `child` | 取反 |
| `hold` | `seconds`、`child` | 子条件**连续**为真 N 秒（断一次就重新计时） |
| `latch` | `set`、`clear` | `set` 成立后锁住，直到 `clear` 成立；**clear 优先** |
| `before` | `first`、`then` | `first` 出现过，之后 `then` 为真 |

老格式的 `fact` 节点（`trigger.vehicle` 这类固定事实）仍然能被解析，解析时自动翻译成
参数化叶子，**下次保存就写回新格式**，不需要手动迁移。

两个实现约定：

- **组合节点不短路**：`all` / `any` 会把每个子节点都求值一遍。否则写在前面的条件为假时，
  后面的 `hold` / `latch` 就不推进状态了，行为会随书写顺序变化；
- **每个节点带内部状态**（`hold._since` / `latch._state` / `before._seen`），`reset()` 全清。
  会话断开、换玩法、换预设、换输入模式时都会清空，避免陈旧状态跨会话生效。

## 5. 规则

```python
Rule(
    id="gta6-driving",
    label="GTA6 · 上车 → 驾驶",
    target="driving",
    enabled=True,
    enter={...条件树...},      # 进入
    leave={...条件树...},      # 退出（None = 永不自动退出）
    enter_hold=0.8,            # 进入去抖（秒）
    leave_delay=1.2,           # 退出去抖（秒）
)
```

- **进入**：规则按列表顺序遍历，`enter` 连续成立 `enter_hold` 秒、目标模式存在、
  目标不是当前模式 → 切过去并记住「是这条规则切的」；
- **退出**：只有**自己切进去的那条规则**才可能自动退出；`leave` 连续成立 `leave_delay`
  秒 → 回默认模式。手动切到目标模式后再被这条规则接管时，只接管退出判定；
- **手动切换**（`mode_switch`）：把当前已成立的规则**压住**，直到它冷掉一次。否则刚切走
  就被切回来，人会以为切换键坏了；
- **优先级**：列表顺序先到先得；已经在某条规则的目标模式里就停在那条规则上，不抢。

### GTA6 驾驶规则（`rulesets/gta6.json`）

```json
{
  "id": "gta6-driving",
  "target": "driving",
  "enter_hold": 0.8,
  "leave_delay": 1.2,
  "enter": {
    "type": "latch",
    "set":   {"type": "trigger", "kind": "resistance", "prefix": "ff03", "side": "both"},
    "clear": {"type": "all", "children": [
      {"type": "interact"},
      {"type": "trigger", "kind": "off", "prefix": "", "side": "both"}
    ]}
  },
  "leave": {"type": "all", "children": [
    {"type": "interact"},
    {"type": "trigger", "kind": "off", "prefix": "", "side": "both"}
  ]}
}
```

读法：**两侧扳机都被设成「阻力 + 参数 FF 03」就进车（不看键盘），锁住；按 △ 且两侧回到
Off 才算下车，1.2 秒后回默认。**

为什么这么写：

- **进车不看键盘**：△（GTA6 的交互键，默认映射 `f`）同时也用来开菜单、拾取，连按几下
  是常态，拿它当判据只会误判。`ffff` 不进车一次都不会切；不按键直接坐进车里也照样切；
- **锁存**：主机只在变化时下发，进车后可能很久没有新包，靠时间窗口续命会自己凉掉；
- **下车要按键**：车位里静止也可能收到 Off，直接当「下车」会误切；
- **按键那一帧最后报的就是 Off**：`interact` 是 3 秒脉冲，所以「人已经在车外再按三角」
  也会立刻成立——两次按键都赶在进车确认之前的情况因此能自己回到默认，不需要额外补丁。

## 6. 配置格式

自动切换的规则**跟按键预设绑在一起**——一个预设 = 一个游戏 = 一套键位 + 一套自动切换规则：

```json
// presets/gta6.json
{
  "preset": "gta6",
  "auto_switch": true,        // 总开关：关掉只是不判定，规则还在
  "auto_hold": 0.8,           // 规则没写自己去抖时继承
  "auto_release": 1.2,
  "rules": [ { "id": "gta6-driving", "target": "driving", "enter": {...}, "leave": {...} } ],
  "modes": { "default": {...}, "driving": {...} }
}
```

- **换预设 = 换游戏 = 换这套规则**，不需要再去别处挑规则集；
- `auto_switch` 是总开关，映射页第三行的「启用」勾的就是它；
- 规则里的「按钮按下」认的是**手柄按钮**（△ / ✕ …）：映射层把键盘翻译成按钮时顺手告诉判定层，
  所以改键位不用回来改规则，也没有额外配置项；
- 坏规则（未知节点 / 未知事实 / 没有目标）会被丢弃并记 warning，其余照常跑；
- 默认模式不能被规则当成目标（配置里写了也会被丢掉），它是回退目标。

**旧配置迁移**（两代都认）：

1. 更早的版本把信号写在模式上（`modes.*.auto_signal` / `auto_leave`）→ 按旧信号生成等价规则；
2. 上一版把规则放在 `rulesets/<预设名>.json` → 加载时若预设里还没有规则，就把那份搬进来
   （`_migrate_legacy_ruleset`，一次性；写盘后就不再读）。

| 旧信号 | 迁移成 |
|---|---|
| `trigger_drive` / `trigger_shoot` / `rumble` / `haptics` | `enter` = 该叶子；`leave` = 取反 |
| `feedback_any` | `enter` = 四种任一；`leave` = 取反 |
| `vehicle_entry` | `enter` = 锁存(置位 阻力·`FF03`·两侧 / 清除 按钮△+Off)；`leave` = 按钮△+Off |
| `auto_leave: false` | 不生成 `leave`（永不自动退出） |

## 7. 界面在哪

**映射页**「预设与模式」卡第三行「自动切换」：

- 左边是**启用**勾选（`auto_switch`，关掉只是不判定，规则不删）；
- 中间是摘要：`2 条规则 → 「驾驶」、「射击」`；
- 右边「编辑规则…」打开**编辑面板（弹窗）**——自动切换只有键鼠玩法才有，所以不占侧栏。

**编辑面板**：

- 顶部一行：`预设「gta6」· 2 条规则` + 「启用自动切换」勾选（和映射页那个是同一个开关）；
- 左边是规则列表（越靠上越先判定），点一行选中；上面有新建 / 复制 / 上移 / 下移 / 删除；
- 右边**第一行就是「满足条件时切到：[驾驶 ▾]」**——一个预设里有多个模式时，这就是告诉规则
  该切到哪一个的地方；只有一个非默认模式时会提示「这个预设只有这一个非默认模式」；
- 往下依次是：启用 / 名称、进入去抖 / 退出延时、进入条件树、退出条件树；
- 条件树每一行左边选类型、右边填参数；`全部满足` / `任一满足` 下面缩进排子条件（`＋条件`），
  `锁存` 分「置位 / 清除」两块，`先后` 分「先 / 后」两块，每行右侧 `×` 删掉它；
  删到分组空了，分组自己降级成一个普通叶子（空分组编译不过）；
- 底部一排**实时信号灯**：亮 = 这个信号现在成立；规则列表每一行也有一盏灯——
  绿色=条件成立，蓝色=当前模式是它切的，黄色=手动切换后被压住。

映射页「预设与模式」卡第三行显示摘要（几条规则、切到哪些模式），旁边有「编辑规则…」
直接跳到这一页。规则跟预设走：换预设 = 换整套规则。

自动切换发生时，日志写一条带原因的记录，例如：

```
规则切模式：「GTA6 · 上车 → 驾驶」成立 → 「驾驶」
规则切模式：「GTA6 · 上车 → 驾驶」条件结束 → 回「默认」
```

排查用日志（`ps5kbm.log`）：主机**只在变化时**下发扳机效果，所以每次变化都留一行，
措辞只说信号本身（两侧有没有效果、类型码是多少），不说「进车 / 步行」——规则引擎不知道
游戏是什么，这句日志也不替它讲故事：

```
扳机信号：两侧无效果 Off → 两侧阻力 FF03（L=21ff0300000000000000 R=21ff0300000000000000）
```

最近 8 帧原始扳机块打在 DEBUG（默认不落盘，`--verbose` 时才写）：
排查「该切没切」先把日志级别开到 DEBUG，再复现一次就能看到连续几帧的 hex。

## 8. 常见问题

| 现象 | 先看什么 | 结论 |
|---|---|---|
| 完全没自动切 | 预设里 `rules` 是不是空的；是不是手柄玩法 | 手柄玩法下映射不影响输入，不判定；规则表为空当然不切 |
| 该切的时候不切 | 日志有没有 `扳机信号：… → 两侧阻力 FF03` | 有 = 信号到了但规则没成立（去看 `enter` 条件 / 去抖）；没有 = 主机没下发带阻力参数的扳机块 |
| 切了马上又回去 | `leave` 条件是不是太容易成立 | 例如 `leave` 只写了 `trigger.off`，停车就会中招 |
| 连按 F 会不会误切 | —— | 不会：进车只看两侧扳机特征，按多少次键都不算证据 |
| 手动切走又自己切回来 | —— | 手动切换会把正成立的规则压到冷掉为止 |
| 规则改了没生效 | 预设是否已保存；是否切到了别的预设 | 规则跟预设走，切预设 = 换整套规则 |

## 9. 扩展指南

- **加一个叶子类型**（新的数据类型，比如「灯条颜色」）：`signal_rules` 里写一个 `Condition`
  子类 → `parse_condition` 挂一行 → `NODE_LABELS` 加显示名 → 给 `SignalWatcher` 加 `feed_*`
  并在 `app.py` 对应回调里调用。规则层与编辑面板的其它部分零改动。
- **扳机只加「类型/前缀/侧」不够用**（比如要按参数区间匹配）：扩 `TriggerCondition` 的参数，
  不要给每个游戏再造一个固定事实——那正是这一版删掉的东西。
- **加一个节点**：`signal_rules` 里写一个 `Condition` 子类，在 `parse_condition` 里挂上，
  `NODE_LABELS` 加一行（编辑页按这张表生成下拉）。记得 `reset()` 清内部状态。
- **想按「次数」判断**（连续震 3 次才切）：加一个计数节点，不要把计数塞进 `hold`。
- **退出切到别的模式**（不是默认）：`RuleEngine._leave` 目前硬编码回 `default`，
  将来加 `Rule.leave_target` 字段即可，条件树不用动。
- **不要做的**：别把「和按键同一帧」当成判据（协议里反馈与输入不同步）；别给扳机事实加
  时间窗口（主机只在变化时下发，加窗口就必然出现「自己凉掉」）。
